# OneScale — бэкенд

Измерение площади объектов по фото с квадратным эталоном и приведение фото к общему масштабу.
Кейс 03 «Один масштаб», Обнинский хакатон 2026. Учебный прототип, не медицинское изделие.

## Запуск

Нужен Python 3.10+.

**Mac / Linux:**
```bash
cd backend
./run.sh
```

**Windows:** двойной клик по `run.bat` (или запустить его в консоли).

Первый запуск сам создаст окружение `.venv` и поставит библиотеки (1–2 минуты).

Вручную то же самое:
```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Проверка: откройте **http://localhost:8000/api/docs** — там все адреса, их можно вызвать прямо из браузера
(кнопка «Try it out»). Фото и результаты хранятся в папке `data/` рядом с кодом.

Тесты: `pip install -r requirements-dev.txt && python -m pytest -q` (257 тестов).

**Сложные фото из Blender** (`tests/fixtures/blender/`, тесты — `tests/test_blender_scenes.py`): 33 отрендеренные сцены —
наклон камеры до 60°, резкая тень, блик на эталоне, вспышка, шум и сжатие JPEG, размытие, коврик с сеткой 1 см,
миллиметровка, тёмные предметы рядом с эталоном, два квадрата, белый эталон на ткани, 8 Мп, серия одного листа,
и 8 контрольных: объективы 24–52 мм с EXIF и без, эталон в центре кадра, поднос не A4, голубой лист на белом столе.
Для каждой сцены в `manifest.json` записана правда: углы эталона и контуры образцов в пикселях, точная площадь в мм².
Фото проходят весь путь, как у пользователя: загрузка → автопоиск эталона → площадь → сравнение с правдой.
Известную слабость можно пометить в `EXPECT` (`issues`) — тест станет `xfail` и «покраснеет», когда её починят.
Пересобрать картинки (нужен Blender 4.2+), из корня репозитория:
`/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P backend/tests/blender/make_scenes.py`.

## Памятка для фронтенда

### Главное правило

**Все координаты (углы эталона, точки обводки) — в пикселях исходного фото**, а не экрана.
Ширина и высота фото есть в ответе (`width`, `height`). Если картинка на экране показана в масштабе `k`,
то точка экрана `(sx, sy)` → точка фото `(sx / k, sy / k)` (с учётом сдвига, если есть зум/прокрутка).

Показывайте пользователю картинку из `urls.file` — она уже повёрнута по EXIF, координаты совпадут.

### Типичный сценарий

```
1. POST /api/images                 загрузить фото → эталон найдётся и откалибруется сам
2. (если эталон не найден или не тот)
   PUT  /api/images/{id}/calibration    {"corners": [[x,y],[x,y],[x,y],[x,y]]}
3. POST /api/images/{id}/measurements   {"points": [[x,y], ...], "label": "Образец 1"}
4. POST /api/compare                    {"image_ids": ["id1","id2"]}  → ссылки на картинки в одном масштабе
5. GET  /api/export.csv                 таблица для Excel
```

### Чьи фото

У каждого браузера свой секретный ключ в cookie `onescale_ws` (его создаёт сайт, см. `frontend/src/lib/workspace.ts`;
запросу без ключа сервер выдаёт новый). Все адреса ниже видят только фото своего ключа: чужое фото — 404,
«выгрузить всё» — только своё. В фото хранится хэш ключа, а не сам ключ.

### Все адреса

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/health` | проверка, что сервер жив |
| POST | `/api/images` | загрузить фото (multipart, поле `files`, можно несколько). Поля формы: `detect` (true), `marker_size_mm`, `group` |
| GET | `/api/images?group=` | список фото со статусом, калибровкой и измерениями |
| GET | `/api/groups` | список групп (серий) |
| GET | `/api/images/{id}` | одно фото |
| PATCH | `/api/images/{id}` | `{"group": "Эксперимент 1", "note": "...", "filename": "..."}` |
| DELETE | `/api/images/{id}` | удалить фото |
| GET | `/api/images/{id}/file` | фото (повёрнутое по EXIF) — **в нём все координаты** |
| GET | `/api/images/{id}/preview?max_side=800` | уменьшенная копия для галереи (заголовок `X-Preview-Scale` — во сколько раз уменьшено) |
| GET | `/api/images/{id}/original` | исходный файл без изменений |
| POST | `/api/images/{id}/detect` | найти эталон заново: `{"polarity": "dark", "marker_size_mm": 10, "auto_calibrate": true}` |
| PUT | `/api/images/{id}/calibration` | задать эталон (см. ниже) |
| DELETE | `/api/images/{id}/calibration` | сбросить калибровку |
| POST | `/api/images/{id}/measurements` | измерить и сохранить обводку |
| PATCH | `/api/images/{id}/measurements/{mid}` | поправить точки/подпись |
| DELETE | `/api/images/{id}/measurements/{mid}` | удалить измерение |
| POST | `/api/images/{id}/autocontour` | «волшебная палочка» (бета): `{"point": [x,y], "tolerance": 25}` → точки обводки; `"union": [[[x,y],...]]` — объединить с уже выделенными областями (`contours_px` — все куски) |
| GET | `/api/images/{id}/standardized?px_per_mm=8&grid=true&annotate=true` | картинка в заданном масштабе |
| POST | `/api/compare` | привести несколько фото к одному масштабу |
| GET | `/api/export.csv?image_ids=a,b` или `?group=` | таблица для Excel (`;`, запятая в числах): файл, площадь мм² и см², периметр, масштаб, дата; `&tz=180` — дата по Москве |
| GET | `/api/export/files?image_ids=a,b&tz=180` | «Сохранить файлы»: фото в общем масштабе, контуры эталона и областей, под фото подпись «имя, площадь, дата». Одно фото — JPG, несколько — ZIP |
| GET | `/api/export.zip` | архив: CSV + отчёт JSON + фото в общем масштабе с сеткой 1 см |

### Статус фото (`status`)

- `uploaded` — загружено, эталон не искали (`detect=false`)
- `marker_not_found` — искали, не нашли → попросите пользователя кликнуть 4 угла
- `marker_found` — найден, но калибровка не применена (`auto_calibrate=false`)
- `calibrated` — можно измерять

### Калибровка (`PUT /api/images/{id}/calibration`)

```jsonc
{"corners": [[78.8,559.3],[170.1,560.5],[170.9,653.9],[79.0,652.9]]}  // 4 угла вручную, порядок любой
{"candidate_index": 1}        // выбрать другой квадрат из detection.candidates
{"marker_size_mm": 30}        // поменять только сторону эталона (углы остаются)
{"perspective": "on"}         // auto | on | off — исправление наклона камеры
```

Что вернётся в `calibration` (главное):
- `corners_px` — 4 угла (по часовой, начиная с левого верхнего) — нарисуйте их и дайте перетаскивать
- `px_per_mm` — масштаб, пикселей в 1 мм
- `uncertainty_pct` — оценка погрешности площади, ±%
- `perspective_used` — включено ли исправление наклона
- `marker_sides_mm` — стороны эталона в мм (если сильно разные — эталон неровный)
- `warnings` — список `{code, message}`; `message` можно показывать пользователю как есть

### Измерение (`POST /api/images/{id}/measurements`)

```jsonc
{"shape": "polygon", "points": [[700,195],[935,190],[940,425],[700,430]], "label": "Образец 1"}
{"shape": "circle", "points": [[500,600],[550,600]]}            // центр + точка на краю
{"shape": "circle", "points": [[x1,y1],[x2,y2],[x3,y3]]}         // 3 точки на окружности
{"shape": "ellipse", "ellipse": {"cx":500,"cy":600,"rx":80,"ry":50,"angle_deg":15}}
{"points": [...], "save": false}                                 // только посчитать (живой предпросмотр)
```

Ответ:
```json
{
  "id": "8fecec3ff8ba", "label": "Образец 1", "shape": "polygon", "points": [[700,195], "..."],
  "area_mm2": 651.67, "area_cm2": 6.517, "perimeter_mm": 102.14,
  "uncertainty_pct": 2.05, "method": "scale",
  "distance_from_marker_sides": 8.15,
  "warnings": [], "calibrated": true, "saved": true
}
```

Если фото переоткалибровать (сдвинуть углы, поменять сторону эталона), площади всех сохранённых
обводок пересчитаются автоматически — точки хранятся в пикселях.

### Сравнение в одном масштабе (`POST /api/compare`)

```json
{"image_ids": ["id1", "id2"], "mode": "scale", "grid": true, "annotate": true}
```
или `{"group": "Эксперимент 1"}`. Необязательно: `px_per_mm` — общий масштаб
(по умолчанию берётся наименьший из выбранных, чтобы ничего не растягивать).

Ответ:
```jsonc
{
  "px_per_mm": 8.046, "one_cm_px": 80.46, "mode": "scale",
  "items": [{
    "image_id": "id1", "filename": "card_top.jpg",
    "url": "/api/images/id1/standardized?px_per_mm=8.046&mode=scale&grid=true&annotate=true",
    "output_size": [1280, 960], "scale_factor": 1.0,
    "marker_corners_out": [[...]],        // эталон в координатах картинки по url
    "measurements": [{"id": "...", "label": "...", "area_mm2": 2653.4, "points_out": [[...]]}]
  }]
}
```
Просто покажите картинки из `url` рядом в натуральную величину — эталон на всех одного размера.
`grid=true` рисует сетку 1 см, `annotate=true` — контур эталона и обводки с площадью.
`mode=rectify` дополнительно выпрямляет наклон камеры (картинку может повернуть по эталону).

### Ошибки

Всегда в одном формате, `message` — по-русски, можно показывать пользователю:
```json
{"detail": {"code": "NOT_CALIBRATED", "message": "Фото «a.jpg» не откалибровано: сначала укажите эталон"}}
```
Частые коды: `NOT_FOUND` (404), `NOT_CALIBRATED` (409), `OUTSIDE_IMAGE`, `SELF_INTERSECTION`,
`TOO_FEW_POINTS`, `MARKER_NOT_CONVEX` (422), `BAD_FILE_TYPE`, `BAD_IMAGE` (415), `FILE_TOO_LARGE` (413).

## Как это работает

1. **Поиск эталона** (без нейросетей): фото делается чёрно-белым несколькими способами, ищутся
   выпуклые четырёхугольники, отбираются похожие на эталон (равные стороны, углы ~90°, ровный тёмный цвет
   внутри — эталон хотя бы втрое темнее фона, поэтому жёлтая или серая наклейка за него не сойдёт).
   Угол, съеденный бликом или закрытый предметом, достраивается по продолжению сторон; цветной тёмный предмет
   (синяя ручка) от бесцветного чёрного эталона отделяется по цвету. Эталон, снятый под 50–65° и сжатый
   на фото вдвое, узнаётся, если на виде сверху, восстановленном по листу, он оказывается квадратом.
   Края уточняются до долей пикселя по профилю яркости **в линейном свете** (размытие объектива и смаз
   происходят в нём, а не в гамма-значениях JPEG — иначе размытый эталон находился меньше настоящего),
   уровень фона берётся у каждой стороны свой. Профили, где у края блик, тень, ручка или линия сетки,
   отбрасываются. Углы — пересечения прямых.
2. **Перспектива** — по убыванию надёжности:
   - **лист бумаги под эталоном** (`plane.py`): его длинные прямые края показывают наклон камеры
     точнее всего. Нужны 4 стороны (углы листа могут быть за кадром) или 3 стороны листа A4/Letter;
     проверка — после исправления углы листа прямые (или ширина листа совпала со стандартной);
   - **сетка на столе** (`grid.py`): коврик для резки, миллиметровка, плитка — линии сетки сходятся в две
     точки схода, как края листа, только линий десятки; проверка — после исправления семейства линий
     перпендикулярны, а линии внутри семейства параллельны;
   - **поза эталона** (`pose.py`): зная фокусное расстояние (из EXIF, без него — как у основной камеры
     телефона, 26 мм), по искажению эталона восстанавливаем, как камера стояла над столом. Если лист виден
     не целиком, его 2–3 видимые стороны уточняют позу: соседние стороны на столе перпендикулярны,
     противоположные — параллельны;
   - только по самому эталону — если перспектива выключена вручную (`perspective: "off"`).
3. **Площадь**: точки обводки переводятся в мм, площадь — по формуле шнурка (Гаусса).
   **Погрешность** считается честно: при «позе» площадь пересчитывается при чуть другом фокусном
   и чуть сдвинутых углах эталона; если у позы есть второе правдоподобное решение, оно тоже входит.
4. **Общий масштаб**: каждое фото масштабируется в `целевой px/мм ÷ px/мм фото` раз.
5. **«Волшебная палочка»**: заливка похожего цвета сначала на уменьшенной копии, затем в полном
   разрешении вокруг найденного объекта; контур сдвигается на настоящий край по доле цвета объекта
   в крайних пикселях — узкие и мелкие объекты больше не теряют 10–30% площади.

На 33 сценах из Blender (наклон до 60°, тени, блики, ручка поверх эталона, размытие, телеобъектив, разные
столы, коврик с сеткой) эталон находится везде, где он есть; средняя ошибка площади — 0,8%, медиана — 0,5%,
хуже 3% — ни одного образца из 58.

### Точность — от чего зависит

- **Размер эталона на фото.** Ошибка в 1 пиксель на эталоне 30 пикс. — это ~7% площади, на 150 пикс. — ~1,3%.
  Снимайте ближе и загружайте фото без сжатия мессенджером.
- **Точность самого эталона.** Квадрат 9,5 мм вместо 10 даёт +10% к площади. Если эталон не ровно 10 мм —
  укажите его реальный размер в `marker_size_mm`. Эталон 3×3 см даёт ошибку в 3 раза меньше.
- **Одна плоскость.** Объект и эталон должны лежать на одной поверхности. Толстые объекты измеряются хуже.
- **Наклон камеры.** Лучше всего — чтобы лист бумаги под образцом целиком попал в кадр: тогда наклон
  исправится по его краям. Без листа наклон оценивается по эталону; это надёжнее, если в фото сохранился
  EXIF (не пересылайте фото через мессенджер). Сайт предупредит, если объект слишком далеко от эталона.

### Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ONESCALE_DATA_DIR` | `./data` | где хранить фото |
| `ONESCALE_MARKER_MM` | `10` | сторона эталона по умолчанию, мм |
| `ONESCALE_MARKER_TOL_MM` | `0.1` | допуск изготовления эталона (входит в ±%) |
| `ONESCALE_TILT_SIDE_RATIO` | `0.08` | с какой «трапецией» включать перспективу в режиме auto |
| `ONESCALE_SMALL_MARKER_PX` | `60` | порог предупреждения «эталон мелкий» |
| `ONESCALE_MAX_UPLOAD_MB` | `1` | максимальный размер файла (сайт сам сжимает фото до 1 МБ) |
| `ONESCALE_MAX_IMAGE_PIXELS` | `50000000` | больше пикселей — фото не распаковывается (защита от «бомб») |
| `ONESCALE_MAX_REQUEST_MB` | `20` | максимальный размер запроса целиком |
| `ONESCALE_MAX_IMAGES_PER_WORKSPACE` | `300` | сколько фото может хранить один браузер |
| `ONESCALE_MIN_FREE_DISK_MB` | `500` | сколько места оставлять на диске: меньше — новые фото не принимаются |

### Структура

```
app/
  main.py         адреса API
  service.py      логика: калибровка, измерения, сравнение, экспорт
  detection.py    поиск эталона
  geometry.py     масштаб, перспектива, площадь
  standardize.py  приведение к масштабу, сетка и подписи
  contour.py      «волшебная палочка»
  plane.py        перспектива по листу бумаги под эталоном
  grid.py         перспектива по сетке на столе (коврик для резки, миллиметровка)
  pose.py         перспектива по позе эталона (фокусное из EXIF или как у телефона)
  imaging.py      чтение фото, поворот по EXIF, HEIC, 16-бит TIFF
  storage.py      хранение на диске
tests/            автотесты на синтетических картинках с известной геометрией
  blender/        генератор сложных сцен в Blender (make_scenes.py)
  fixtures/       готовые фото сцен и manifest.json с правдой
```
